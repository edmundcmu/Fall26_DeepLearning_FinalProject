# Validity notes and evidence boundary

1. **Physical scope.** The downloaded data contain Cu54 and Cu54H2 only. The two-H subset can include molecular and dissociated configurations; the formula alone does not identify that state. Do not delete H, relabel these as Cu54H, or claim isolated-H diffusion. No MD/barrier reference was acquired in this package.
2. **Source-version mismatch.** The paper reports 4,230 structures. The pinned current file contains 4,220; its filename indicates a processed export. We cannot establish the reason for the ten-record difference from the file alone. Three further exactly duplicated records are removed only after verifying identical positions, energies and forces. The pipeline uses the measured counts, not the paper's counts or another repository's 3,413-record subset.
3. **DFT versus MACE predictions.** The labels are the published DFT reference database associated with MLIP/MACE research, not MACE-generated pseudo-labels. SRP48/FHI-aims is the literature reference. The `e0` export energy zero is retained; exact isolated-atom offsets are not reconstructed or asserted to be absolute FHI-aims total energies.
4. **Transfer reference.** UMA's catalyst task `oc20` is a starting condition, not an SRP48 switch. UMA-M's pretrained error against these labels combines domain transfer and reference-method mismatch. Both U0 and adapted predictions use `oc20`; the adapted model's learned target is the supplied data. No claim of reproducing published UMA OC20 benchmarks follows.
5. **No trajectory IDs.** The export has only `config_type` metadata. We therefore use disjoint simulation-cell families. This is an explicitly harder group-held-out protocol rather than a randomized frame split. It prevents identical-cell fixed-cell trajectories from crossing the split, but it does not prove all parent-structure or pretraining relationships are absent. A changed task requires a new predeclared protocol, not post-test rerolling.
6. **No mobility/constraint metadata.** The source export contains no ASE constraints. The paper describes fixed bottom layers for some sampling, but this cannot be reconstructed unambiguously frame by frame. The pipeline preserves and scores all supplied force labels. It must not describe these as movable-atom-only metrics. Zeroing forces on guessed frozen layers would change the task.
7. **Data representation.** Preserve element ordering, cell, all three periodic flags, positions in Å, energies in eV, and Cartesian forces in eV/Å. Use `get_forces(apply_constraint=False)` for reference labels. The vacuum direction is still periodic in the original export. Do not invent stress or convert slab stresses using an arbitrary vacuum thickness.
8. **Energy convention.** Training-only references/normalization are used. In inference reporting, show raw energies and train-composition-offset-aligned energies separately. Do not fit offsets on validation/test. A per-composition offset is valid for within-composition comparisons but does not establish reaction/adsorption energies across compositions.
9. **Full-transfer baseline definition.** The pinned official pipeline replaces the EFS head and trains the backbone. Its loss differs from Eq. (2) in IDL.pdf. Calling it a head-preserving, frozen, species-balanced, adapter, or Force-Gradient baseline would be incorrect. It is an initial native-upstream transfer benchmark; future method comparisons need a shared objective and shared initialization policy.
10. **Metrics.** Primary reporting is H Cartesian-component MAE in eV/Å. Cu and whole-configuration energy errors are separate safeguards. A vector norm is not componentwise MAE; energy per atom is not energy per configuration. The zero-force reference values are real computations but are not MLIP performance.
11. **Pretrained model contamination.** Pretraining overlap with this literature database has not been audited. An old MACE checkpoint trained on the full database cannot be presented as held-out on the new test split. Train/fine-tune a MACE comparator only on this training subset, or mark the pretrained comparison as potentially exposed.
12. **Training cost and readiness.** Actual UMA-M parameter counts, force-loss gradients, optimizer/EMA memory and GPU timing require the GPU pilot. The literature's active inference count is not the optimizer parameter count. No fitting success, accuracy gain, CUDA-memory requirement, or budget guarantee is claimed here. Syntax and CPU tests cannot certify the GPU path.
13. **Evidence needed next.** Approved model access; a CUDA environment; pinned environment/checkpoint hashes; two finite training updates; validation inference from the saved checkpoint; final fixed-step runs; locked test metrics; and at least three repeats before comparative statistical claims. The two-step pilot tests execution, not convergence.
