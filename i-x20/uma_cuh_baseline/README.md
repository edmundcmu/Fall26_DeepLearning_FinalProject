# UMA-M Cu/H transfer baseline starter

This package downloads and audits **DFT reference labels used in the MACE-associated Cu/H research lineage**, then prepares an ordinary UMA-M transfer-learning baseline. The labels are not generated by MACE. No adapters or selection algorithm are implemented here.

**Current evidence:** real data downloaded; label/structure audit and split executed; CPU data/metric tests executed. UMA inference and GPU training have NOT been executed. See `reports/SECTION_5_1.md` for the report-ready evidence statement and `reports/VALIDITY_NOTES.md` for limitations.

## Fixed artifacts

- Dataset: `wgst/ml-gas-surface`, commit `72db5df1f152c86afa4de98af628b1a67268445b`, file `databases/h2cu/pes/h2cu_20220529_as4_forces_red_clr20240208_e0.xyz`.
- FAIRChem: commit `645af7d03e91138ef07e51de387316c9e2e152dc`.
- Model: `facebook/UMA`, **uma-m-1p1**, revision `c5107e43d5e811dd7cb56f57533dc0eb550dee6b`. Use `source_lock.json`, not an automatically changing `latest` alias.
- Conditioning task: `oc20` as the starting catalyst domain. Target labels are **SRP48**, not the pretrained OC20 RPBE target. This is cross-reference transfer, not a claim that the two theories match.
- Scope approved for this stage: Cu/H energy-and-force prediction. There are **zero single-H structures**. No isolated-H diffusion, diffusion coefficient, or barrier claim is supported by this data audit.

## What is already present

`data/raw/h2cu.xyz` is the unchanged 25,174,977-byte download. `data/prepared/` contains train/validation/test extxyz files and a manifest with original row indices, file hashes, cell groups, and composition counts. Three identically labelled exact duplicates were removed. The original raw file remains unchanged.

The data have four cell families after rounding cell entries to 1e-6 Å. The oblique in-plane cell family is reserved for testing; the shortest-a rectangular family validates; the other two train. Seed 20261023 selects 500/100/200 configurations, stratified by composition. This is a deliberately different **cell-family-held-out** protocol, not reproduction of a published random split. Unused records are not additional training data. There is no selection set yet because adapters are deferred.

## CPU setup and reproduction

From this package directory, use a fresh Python 3.12 environment:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-data.txt
python scripts/fetch_data.py
python -m pytest -q tests
```

The prepared split is already included. To regenerate it, preserve/move `data/prepared` first, then run `python scripts/prepare_data.py`. The script refuses to overwrite an existing split. Do not reroll the seed based on validation or test performance.

## GPU setup

Use a fresh **Linux NVIDIA GPU environment** allocated through your cluster. No scheduler account, GPU access, or cluster connection is assumed by this package. Do not run training on a login node.

```bash
bash scripts/setup_gpu.sh
hf auth login
python scripts/fetch_checkpoint.py
```

The user must already have approved access to https://huggingface.co/facebook/UMA. Authentication alone does not grant access. Do not put a token into this repository. The checkpoint downloader pins the HF revision and records the downloaded file's SHA-256.

The checked FAIRChem source currently declares `torch~=2.13.0`, Python >=3.11,<3.15, and Linux CUDA dependencies. This installation has NOT been tested here. Inspect installation errors rather than silently switching to a different release; changing the source requires rechecking the API/config and rerunning the smoke test. The repository layout is `packages/fairchem-core`, not the older `src/packages` path shown in some tutorials.

UMA-M full training can require much more memory than its active inference parameter count suggests. Start with batch size 1. No fit-to-48GB or $400 budget guarantee is made. Profile a two-step run before scheduling 2,000 updates.

Training checkpoints also contain optimizer and EMA state and can occupy tens of GB each. The starter saves an initial and a final checkpoint rather than many intermediate copies; confirm scratch space before running.

## U0: evaluate the untouched pretrained model

```bash
python scripts/evaluate.py \
  --checkpoint checkpoints/checkpoints/uma-m-1p1.pt \
  --label U0 --split val --output reports/U0_val
```

Evaluation uses `traineval`: FP32, no TF32, no model merging/compilation. It predicts training configurations first to fit composition-specific constant energy offsets. These offsets never use validation/test labels. Both raw and offset-aligned energy errors are retained. Energy offsets do not change forces and do not establish an adsorption-energy reference across compositions.

`metrics.json` records H/Cu Cartesian-component MAE and RMSE in eV/Å, whole-configuration and per-atom energy errors, the checkpoint/data hashes, inference settings, and inference time/memory. `*_predictions.npz` saves frame-indexed predictions for later paired analysis. Report componentwise errors, not vector-norm errors under the same name.

## Two-step GPU acceptance run

```bash
python scripts/build_finetune.py --fairchem external/fairchem \
  --output runs/smoke_config --steps 2 --seed 41
export PYTHONPATH="$PWD/scripts${PYTHONPATH:+:$PYTHONPATH}"
set -o pipefail
fairchem -c runs/smoke_config/uma_sm_finetune_template.yaml 2>&1 | tee runs/smoke_training.log
```

`build_finetune.py` calls the pinned upstream converter using the verified `--regression-tasks ef` flag. The official script's template filename says `sm`, but the generated configuration explicitly selects **UMA-M**. Conversion counts and failed-record logs are checked. Training/validation only are converted; the locked test set is never passed to training.

Acceptance: two completed updates, finite losses and gradients, a saved `final/inference_ckpt.pt`, and successful subsequent validation inference. The custom audit callback records actual total/trainable parameters, step losses, wall time and peak allocated GPU memory. The first two steps incur additional gradient-audit overhead. An import/compile test is not a successful GPU acceptance run.

## Full baseline run

```bash
python scripts/build_finetune.py --fairchem external/fairchem \
  --output runs/full_config_seed41 --steps 2000 --seed 41
export PYTHONPATH="$PWD/scripts${PYTHONPATH:+:$PYTHONPATH}"
set -o pipefail
fairchem -c runs/full_config_seed41/uma_sm_finetune_template.yaml 2>&1 | tee runs/full_training_seed41.log
```

This starts again from the pinned pretrained checkpoint, not from the two-step pilot. The setup uses AdamW, learning rate 1e-4, weight decay 1e-3, batch size 1, the upstream cosine scheduler, gradient clipping 10, EMA 0.999, and a fixed final-step checkpoint. Training and validation use the seed in the generated protocol. Other seeds should use separate configuration/run directories. For a meaningful comparison use at least three repeats (e.g. 41,42,43) once feasibility is established; report mean/spread, not a favorable seed.

**Head policy:** the official converter installs a new conservative `MLP_EFS_Head`; the pretrained backbone is fully trainable. This is full-backbone transfer with a reinitialized head, NOT a head-preserving update and NOT a Force-Gradient adapter baseline. Compare with U0 under these labels. The new head derives forces from energy. Do not train through the ASE inference calculator or use `torch.no_grad()` around force training.

**Loss:** retained upstream objective: 20 × per-atom energy MAE + 2 × mean force-vector L2 error, with element references and a shared force-RMS scale fitted on training data. This is NOT the report's Eq. (2) species-balanced normalized MSE. H-specific evaluation is provided, but the training loss is not species balanced. Before an adapter comparison, choose and implement one common loss for every adapted method. Stress labels are absent, so stress training/inference tasks are removed from this generated training configuration.

Evaluate the fixed final checkpoint printed in the training logs:

```bash
python scripts/evaluate.py --checkpoint /absolute/path/to/final/inference_ckpt.pt \
  --label full-transfer-seed41 --split val --output reports/full_seed41_val
```

Use the final step selected before test evaluation. If the pilot reveals a problem, revise the protocol on training/validation only and document it. A final checkpoint is not necessarily the best-validation checkpoint; this starter deliberately uses a fixed-step rule.

## Locked test evaluation

After fixing the protocol and recording the checkpoint choice:

```bash
python scripts/evaluate.py --checkpoint /absolute/path/to/final/inference_ckpt.pt \
  --label full-transfer-seed41 --split test --unlock-test \
  --selection-record runs/full_config_seed41/baseline_protocol.json \
  --output reports/full_seed41_test
python scripts/evaluate.py --checkpoint checkpoints/checkpoints/uma-m-1p1.pt \
  --label U0 --split test --unlock-test \
  --selection-record runs/full_config_seed41/baseline_protocol.json \
  --output reports/U0_test
```

The explicit switch is a procedural guard, not cryptographic access control. The preparation script computes a fixed zero-force/constant-energy sanity reference; those descriptive test-label summaries must not be used to choose hyperparameters or splits.

## Report and evidence

`reports/SECTION_5_1.md` is an English replacement draft. `reports/baseline_status.csv` distinguishes executed CPU statistics from pending UMA results. No published UMA or MACE score has been copied into a purported new run. Later append metrics from the evaluation JSONs and attach actual logs.

After collecting evaluation results, run `python scripts/summarize_results.py` to refresh the CSV. This reads measured JSONs; absent runs remain `NOT RUN`. Update the prose separately so the report's evidence date and scope remain clear.

The current package does not meet the original PDF's specific Force-Gradient adaptation requirement: that method was explicitly deferred in this request. It establishes an ordinary transfer baseline and the data/evaluation foundation.
